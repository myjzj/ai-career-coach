# W04 · Prompt、结构化输出与工具调用

> 阶段：LLM 与 RAG 核心（P1）｜Day 1–7
> 用法：先读当天小节，再去做学习舱任务；做完回来补“常见坑”。

## 本周主线

- 把 prompt 从“玄学”变成有契约、有版本、有评测的工程。
- 让模型输出可校验的数据，并知道解析失败怎么兜底。
- 理解 function calling 的责任边界，以及 prompt injection 的纵深防御。

## Day 1 · Prompt 基础与模式

**一句话**：好 prompt 不是“请一步步思考”，而是把任务、约束、输入、输出格式说清楚。

**核心知识**

- 五要素：角色/任务、输入数据、约束、输出格式、示例。
- zero-shot 适合通用任务；few-shot 用 3–5 个覆盖边界和难例的示例。
- CoT 对复杂推理有帮助，但会增加 token、可能泄露推理；简单任务不必默认开启。
- 指令冲突会让模型无所适从；系统指令、用户指令、数据要分层标记。
- prompt 要版本化：版本、改动、评测结果、失败案例都要记录。

**速查**

```text
[任务] 你是简历匹配助手，评估候选人与 JD 的匹配度。
[输入] <jd>...</jd> <resume>...</resume>
[约束] 只依据输入；证据不足时写“无法判断”；不得编造经历。
[输出] JSON：score(0-100), strengths[], gaps[], evidence[], next_actions[]
```

**常见坑**

- 一次塞入多个互相冲突的目标（既要简短又要详尽），模型只能猜。
- 只改 prompt 不看评测，越改越“感觉良好”。

**面试口述**

> few-shot 的示例怎么选？示例越多越好吗？

**任务关联**：3 版 prompt / 5 条样本对比 / prompt 版本表

## Day 2 · 结构化输出与 JSON Schema

**一句话**：让模型输出 JSON 只是第一步，能校验、能重试、能降级才是工程。

**核心知识**

- JSON Schema 定义字段、类型、枚举、必填、范围；Pydantic 可在应用侧二次校验。
- JSON mode 只保证语法上是 JSON，不保证字段和语义正确。
- 解析失败时把错误信息带回模型重试；仍失败则降级为文本 + 人工处理。
- 让模型输出 `evidence` 字段，把结论和原文绑定，降低胡编。
- 流式结构化输出要处理半截 JSON，通常先累积再解析，或使用增量解析器。

**速查**

```python
class MatchReport(BaseModel):
    score: int = Field(ge=0, le=100)
    strengths: list[str]
    gaps: list[str]
    evidence: list[str]
    next_actions: list[str]
```

**常见坑**

- 用正则/eval 硬修 JSON；eval 有安全风险，正则修不好嵌套结构。
- schema 太复杂，模型字段合法率下降；先简化，再逐步加约束。

**面试口述**

> 模型输出的 JSON 解析失败，你怎么处理？为什么不能直接 eval？

**任务关联**：MatchReport schema / 20 条合法率 / 重试策略

## Day 3 · Function Calling 与工具调用

**一句话**：模型只输出“调用意图”，真正执行、校验和负责的是应用。

**核心知识**

- tool schema 包含名称、描述、参数 JSON Schema；描述要写清何时用、何时不用。
- 模型返回 tool name + arguments；应用校验参数、执行、把结果作为 observation 回传。
- 并行工具调用可以减少轮次，但要注意依赖关系和结果顺序。
- 工具错误要结构化返回（类型/原因/是否可重试），让模型能决定重试/换工具/终止。
- 高风险工具（写库、发通知、执行 SQL）要加权限、审批、幂等和审计。

**速查**

```json
{
  "name": "search_jobs",
  "description": "按关键词查询职位库；当用户询问岗位机会时使用",
  "parameters": {
    "type": "object",
    "properties": {"keyword": {"type": "string"}, "city": {"type": "string"}},
    "required": ["keyword"]
  }
}
```

**常见坑**

- 让模型直接拼 SQL/shell；必须参数化、白名单、最小权限。
- 工具描述含糊，模型选错工具；描述本身就是 prompt 的一部分。

**面试口述**

> function calling 是模型执行函数吗？权限和幂等应该放在哪一层？

**任务关联**：3 个工具 / 调用循环 / 参数正确率

## Day 4 · Prompt Injection 与安全边界

**一句话**：把检索到的文档、网页、工具结果都当成“不可信输入”，而不是指令。

**核心知识**

- 直接注入：用户在输入里写“忽略以上指令”；间接注入：恶意内容藏在文档/网页/工具结果里。
- 模型难以可靠区分“指令”和“数据”，所以不能只靠 prompt 防御。
- 纵深防御：最小权限、工具白名单、输入隔离/标记、输出校验、人工审批、审计。
- 系统提示泄露、数据外泄、越权工具调用是三类高频风险。
- 安全测试要进入回归集，不能上线前才做一次。

**速查**

```text
防御清单：
[ ] 工具最小权限 + 白名单
[ ] 高风险动作审批
[ ] 不把用户输入拼进 SQL/shell
[ ] 检索内容标记为不可信数据
[ ] 输出做格式/敏感信息校验
[ ] 记录审计日志
```

**常见坑**

- 在 prompt 里写“不要听用户的”就以为安全；攻击者可以间接注入。
- 只防输入不防输出；模型可能泄露系统提示或内部数据。

**面试口述**

> 为什么“在 prompt 里写不要听用户的”不够？你会怎么设计防御？

**任务关联**：10 条攻击样本 / 防御清单 / 安全测试报告

## Day 5 · 评测与 LLM-as-judge

**一句话**：没有评测集的 prompt 优化都是玄学。

**核心知识**

- 评测集结构：输入、参考答案、评分 rubric、相关证据；覆盖简单/边界/无答案/对抗样本。
- 指标：字段合法率、准确率、忠实度、引用命中、延迟、成本。
- LLM-as-judge 有位置偏差、长度偏好、自我偏好、对 prompt 敏感等问题。
- 用人工标注校准 judge；固定 rubric；交换顺序/双盲；抽检。
- 保留 held-out 集，调参不能反复看它，否则会过拟合。

**速查**

```text
评测报告：数据集版本 / 指标 / baseline / 新版本 / 失败案例 / 结论
```

**常见坑**

- 用模型生成评测题，再让同一个模型评分；自我循环，分数虚高。
- 只看平均分，不看失败分布；长尾错误可能更致命。

**面试口述**

> LLM-as-judge 有什么风险？你怎么校准它？

**任务关联**：20 条标注样本 / 3 个指标 / 评测报告

## Day 6 · Lab：JD–简历结构化匹配器

**一句话**：把 prompt、schema、工具、评测串成一个小产品，而不是一堆脚本。

**核心知识**

- 输入清洗：JD/简历去噪、分段、长度控制；敏感信息脱敏。
- 输出契约：匹配分、优势、缺口、证据、下一步建议。
- 证据字段要引用原文片段，便于人工复核和自动校验。
- 批量处理要控制并发、限流、重试和成本。
- README 要写清适用边界和失败案例，主动暴露局限。

**速查**

```text
链路：读取 → 清洗 → prompt → JSON → Pydantic 校验 → 重试/降级 → 报告
```

**常见坑**

- 只展示“匹配成功”的样例；面试官会问失败案例。
- 评分没有 rubric，10 个人看出 10 个分数。

**面试口述**

> 这个项目怎么防止“看起来很准”？你用什么指标证明它有效？

**任务关联**：真实样本 / 批量处理 / README / 失败案例

## Day 7 · 周复盘：Prompt 与工具调用

**一句话**：Prompt 是接口契约，评测是回归测试，安全是上线前提。

**核心知识**

- 能解释 prompt 五要素和 CoT 的适用边界。
- 能设计 JSON Schema、处理解析失败和降级。
- 能说清 function calling 的责任边界和工具安全。
- 能列出 prompt injection 的至少 5 种防御手段。

**速查**

```text
本周最小验收：
[ ] 3 版 prompt 有对比数据
[ ] 结构化输出合法率 ≥ 95%
[ ] 10 条注入样本有测试结果
[ ] 能讲清 judge 偏差
[ ] 匹配器可演示
```

**常见坑**

- 把“模型很聪明”当工程方案；边界、失败、成本才是工程。
- 安全只在最后补，结果要重构整个工具层。

**面试口述**

> 用 2 分钟讲你怎么把 prompt 工程化。

**任务关联**：W4 周测 / prompt 模板库 / 周报 / 简历 bullet
