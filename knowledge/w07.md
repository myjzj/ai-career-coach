## 本周主线

- 先定问题、SLO、数据模型和权限，再写代码。
- 完成上传 → 解析 → 索引 → 问答 → 引用的主链路。
- 多租户隔离必须贯穿数据、检索、缓存和审计。

## Day 1 · 需求、架构与验收指标

**一句话**：项目一开始就要知道“什么算成功”，否则做完只是 demo。

**核心知识**

- 需求：谁用、问什么、文档从哪来、答错/答不出怎么处理。
- SLO：召回、忠实度、P95 首 token、可用性、单次成本。
- 数据模型：tenant、doc、chunk、conversation、message、task。
- 威胁模型：越权、注入、数据泄露、恶意文件、成本攻击。
- 架构：接入层、ingestion、检索、生成、评测、观测、运维。

**速查**

```text
验收指标示例：
Recall@5 ≥ 0.85 / 忠实度 ≥ 0.85 / 引用命中 ≥ 0.8 /
P95 首 token < 2.5s / 单次成本 < 0.02 元
```

**常见坑**

- 先选技术栈再想需求，最后发现向量库/模型不匹配。
- 没有基线，做完不知道有没有变好。

**面试口述**

> 为什么项目一开始就要定评测集和 SLO？

**任务关联**：PRD / 架构图 / ER 图 / API 契约 / 风险清单

## Day 2 · Ingestion：上传、解析、切分、入库

**一句话**：文档处理是长耗时、易失败的流水线，必须异步、可重试、可观测。

**核心知识**

- 上传：大小/类型限制、病毒扫描、租户校验、存储路径隔离。
- 解析：PDF/Word/Markdown，保留标题、页码、表格；失败要记录原因。
- 切分：按结构 + token 上限 + overlap；写入 metadata。
- 去重：内容 hash + 唯一约束；更新用版本号/upsert。
- 任务表：status、error、retry_count、doc_id；失败可重入，死信可人工处理。

**速查**

```text
upload → parse → clean → split → embed → upsert → ready
              ↘ failed → retry → dead letter
```

**常见坑**

- 同步解析大文件，HTTP 超时，用户以为失败又重复上传。
- 只追加新 chunk 不删旧版本，召回过期内容。

**面试口述**

> ingestion 为什么要异步？怎么保证可重试和幂等？

**任务关联**：上传接口 / 解析 / 切分 / 任务表 / 3 个样本

## Day 3 · 索引与检索

**一句话**：索引是“可重建的派生数据”，要能增量更新和一致性校验。

**核心知识**

- embedding 批处理 + 限流 + 失败重试；记录模型版本和维度。
- pgvector 建 HNSW；写入时带 tenant/doc/version metadata。
- 检索：dense + BM25 + filter；先过滤再召回，避免越权和数量不足。
- 增量索引：文档 id + 内容 hash + 版本；旧 chunk 删除/标记失效。
- 一致性校验：文档数、chunk 数、索引数对账；失败任务重跑。

**速查**

```sql
SELECT id, content, 1 - (embedding <=> :q) AS score
FROM chunks
WHERE tenant_id = :tenant AND doc_version = :version
ORDER BY embedding <=> :q
LIMIT 20;
```

**常见坑**

- 向量库和元数据分两套写，事务不一致，出现“有向量没原文”。
- 更新文档只改内容不换版本，缓存和引用指向旧内容。

**面试口述**

> 增量索引怎么避免重复和漏索引？

**任务关联**：embedding 批处理 / HNSW / hybrid / 增量更新

## Day 4 · 问答、引用与拒答

**一句话**：先保证“有据可查”，再追求“答得漂亮”。

**核心知识**

- 上下文拼装：按相关性排序、去重、控制 token、保留来源。
- 引用：chunk id + 原文片段 + 页码/段落；生成后校验。
- 拒答：检索分数 + 模型判断 + 无有效引用；阈值用评测集调。
- 流式回答：先返回检索状态/引用，再流式输出正文，体验更好。
- 会话历史只带最近相关轮次，避免上下文污染。

**速查**

```text
System：只依据 <context> 回答；每个结论标注 [n]；
无证据时拒绝，并说明缺少什么。
```

**常见坑**

- 引用只显示文档名，无法定位；用户无法验证。
- 把“不知道”写成“根据资料……”然后编造，仍算幻觉。

**面试口述**

> 拒答策略怎么设计？误拒和漏拒怎么权衡？

**任务关联**：/chat / 引用 / 拒答 / 20 条问答测试

## Day 5 · 多租户与权限

**一句话**：最危险的实现是“先全库召回，再在应用层过滤”。

**核心知识**

- tenant_id 进入所有表、chunk metadata、检索条件、缓存 key、日志。
- 数据库行级安全（RLS）可作为第二道防线；应用层仍要校验。
- API 鉴权：JWT/API key → 租户/用户 → 权限；不要只信前端。
- 缓存 key：tenant + doc version + query hash；否则串答案。
- 审计：谁在何时问了什么、命中了哪些文档、返回了什么。

**速查**

```text
请求 → 鉴权 → 解析租户 → 检索 filter(tenant) → 生成 → 返回前再校验
```

**常见坑**

- 只在应用层过滤，top-k 先被其他租户内容占满，召回不足且越权。
- 缓存 key 不带租户/版本，A 租户看到 B 租户答案。

**面试口述**

> 多租户向量检索怎么防止越权？为什么要“检索前过滤”？

**任务关联**：tenant 模型 / 强制 filter / 10 个越权用例 / 审计

## Day 6 · 集成、端到端测试与 demo

**一句话**：演示不是展示功能列表，而是讲清一个真实问题如何被解决。

**核心知识**

- 最小 UI/CLI：上传、索引状态、提问、引用、拒答。
- 端到端测试：上传 → 解析 → 索引 → 问答 → 引用完整链路。
- 错误状态要可见：解析失败、索引中、无权限、上游超时。
- demo 脚本：问题 → 约束 → 架构 → 现场操作 → 指标 → 失败案例。
- 录屏 3 分钟，先讲价值再讲技术栈。

**速查**

```text
Demo 顺序：
1. 上传一份真实文档
2. 问一个文档里有答案的问题
3. 展示引用
4. 问一个文档里没有的问题，展示拒答
5. 展示评测指标与限制
```

**常见坑**

- 演示时网络/模型超时，没有离线兜底或预置结果。
- 只演示成功路径，面试官一问边界就卡住。

**面试口述**

> 演示项目时怎么讲架构？先讲什么、后讲什么？

**任务关联**：最小界面 / 端到端测试 / demo 脚本 / README v1

## Day 7 · 周复盘：项目一主链路

**一句话**：主链路稳、指标真、权限不漏，比功能多更重要。

**核心知识**

- 对照验收指标自测：召回、忠实度、引用、延迟、成本。
- 列出最大风险：权限、性能、评测、成本、体验。
- 项目复盘：完成了什么、没完成什么、下周优先级。
- 准备生产化清单：容器、缓存、监控、压测、文档。

**速查**

```text
本周最小验收：
[ ] 上传 3 种格式
[ ] 引用可定位
[ ] 无答案可拒答
[ ] 越权测试全过
[ ] 端到端 demo 可跑
```

**常见坑**

- 主链路还有硬编码/手工步骤，却开始加新功能。
- 没有真实文档样本，评测和演示都不可信。

**面试口述**

> 项目一当前最大的风险是什么？你准备怎么修？

**任务关联**：W7 周测 / 验收自测 / 风险清单 / 周报
