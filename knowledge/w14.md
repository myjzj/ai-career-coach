# W14 · AI 系统设计、ML 八股与算法

> 阶段：求职冲刺（P5）｜Day 1–7
> 用法：先读当天小节，再去做学习舱任务；做完回来补“常见坑”。

## 本周主线

- 把项目经验抽象成可复用的系统设计答案。
- 补齐 Transformer/ML 高频八股，能一句话说清再展开。
- 算法按模式刷，稳定在 25 分钟内写出可运行代码。

## Day 1 · 系统设计框架与 RAG 设计

**一句话**：先对齐需求与约束，再画架构；不要一上来堆组件。

**核心知识**

- 回答结构：功能/非功能 → 规模估算 → 数据模型 → 核心链路 → 瓶颈 → 取舍。
- 先问三件事：数据规模/类型、用户/租户/权限、质量与延迟/成本 SLO。
- RAG 核心：ingestion、检索、rerank、生成、引用、评测、观测。
- 容量：QPS × token × 单价；峰值、缓存、冗余。
- 失败模式：召回漏、上下文噪声、模型不用证据、越权、成本失控。

**速查**

```text
1. 需求与 SLO
2. 规模估算（文档数/QPS/token/存储）
3. 架构图
4. 核心链路与数据模型
5. 瓶颈与扩展
6. 取舍与失败模式
```

**常见坑**

- 直接画向量库/模型，没问数据规模和权限。
- 只讲正常路径，不讲失败/降级/成本。

**面试口述**

> 设计企业 RAG 平台，先问哪三个问题？

**深入理解**
- **机制**：系统设计先对齐功能/非功能、规模、数据模型和 SLO，再画架构。
- **边界**：不估规模会选错存储；不问权限会埋越权；只画正常路径会被追问故障。
**场景**：企业 RAG：文档规模、租户/权限、质量/延迟/成本 SLO，再选切分/向量库/模型/缓存。
**追问**：Q：先问哪三个问题？A：数据规模/类型、用户/租户/权限、质量/延迟/成本 SLO。

**任务关联**：2 道 RAG 设计提纲 / 35 分钟口述 / 录音复盘

## Day 2 · Agent 平台与模型网关设计

**一句话**：Agent 平台的核心是状态、工具、权限、审批和观测，不是多智能体。

**核心知识**

- Agent 平台：API、编排引擎、工具运行时、状态存储、trace、评测。
- 工具协议：schema、超时、错误、幂等、权限、沙箱。
- 长任务：队列、checkpoint、恢复、取消、超时。
- 模型网关：统一协议、路由、配额、熔断、降级、计量。
- 安全：工具白名单、人工审批、审计、租户隔离。

**速查**

```text
Agent 请求 → 编排 → 工具（沙箱）→ 状态/checkpoint
                    ↘ 审批 → 恢复
                    ↘ trace/评测/成本
```

**常见坑**

- 把 Agent 平台设计成“prompt 管理器”，没有状态和工具治理。
- 网关只做转发，没有配额/熔断/降级。

**面试口述**

> 设计 Agent 平台的核心难点是什么？

**深入理解**
- **机制**：Agent 平台 = API + 编排引擎 + 工具运行时 + 状态存储 + trace + 评测。
- **边界**：工具权限、状态持久化、审批、死循环和成本是核心难点；多 agent 不是默认。
**场景**：先做单 agent 闭环，再加审批、恢复、多 agent。
**追问**：Q：Agent 平台最难的是什么？A：可控性：权限、状态、审批、观测和评测。

**任务关联**：2 道设计提纲 / 35 分钟口述 / 瓶颈清单

## Day 3 · Transformer 与 ML 八股

**一句话**：八股要能一句话说清，再展开一层；不要背长段落。

**核心知识**

- Attention：QKV、缩放、多头、位置编码、复杂度 O(n²)。
- 归一化：LayerNorm 逐样本特征维，适合变长序列；BatchNorm 依赖 batch。
- 偏差-方差：欠拟合/过拟合；正则、早停、更多数据、简化模型。
- 评估：准确率/ precision/recall/F1/AUC；类别不平衡看 PR/F1。
- 过拟合信号：训练好、验证差；数据泄漏会让分数虚高。

**速查**

```text
Anti-overfit：更多数据 / 正则 / dropout / 早停 / 简化模型 / 数据增强
```

**常见坑**

- 只背公式，不能解释“为什么这样设计”。
- 把 LayerNorm/BatchNorm 的维度说反。

**面试口述**

> LayerNorm 和 BatchNorm 的区别？为什么 Transformer 常用 LayerNorm？

**深入理解**
- **机制**：Transformer 的核心是 attention + FFN + 残差 + 归一化；LayerNorm 逐样本在特征维归一化。
- **边界**：BatchNorm 依赖 batch，变长序列不稳定；attention 是 O(n²)；过拟合/欠拟合要看训练/验证差距。
**场景**：面试先一句话说清，再展开公式和工程影响。
**追问**：Q：LayerNorm 和 BatchNorm 的区别？A：逐样本特征维 vs batch 维；Transformer 常用 LayerNorm。

**任务关联**：50 道速答 / 错题 / 一页速查

## Day 4 · 算法模板：8 类高频模式

**一句话**：刷题不是比数量，是看到题能反射出模式。

**核心知识**

- 哈希：计数、去重、前缀和配合。
- 双指针：有序数组、去重、三数之和。
- 滑动窗口：连续子数组/子串的最长/最短。
- 二分：有序、答案单调、边界查找。
- 堆：前 K 个、合并 K 个、流式中位数。
- 图：BFS/DFS、拓扑排序、并查集。
- DP：最优子结构、状态定义、转移、边界。
- 回溯：组合/排列/子集，注意剪枝。

**速查**

```text
连续子数组/子串 → 滑窗/前缀和/DP
前 K 个 → 堆/快速选择
最短路径 → BFS/Dijkstra
依赖顺序 → 拓扑排序
```

**常见坑**

- 只写代码不分析复杂度，面试官会追问。
- 不处理空输入/边界/重复元素。

**面试口述**

> 看到“连续子数组/子串”优先想什么？看到“前 K 个”呢？

**深入理解**
- **机制**：算法题先识别模式：哈希、双指针、滑窗、二分、堆、图、DP、回溯。
- **边界**：连续子数组看滑窗/前缀和/DP；前 K 个看堆/快速选择；依赖顺序看拓扑。
**场景**：25 分钟内写出可运行代码，先讲思路和复杂度，再处理边界。
**追问**：Q：看到连续子数组/子串优先想什么？A：滑窗；有负数区间和可考虑前缀和/DP。

**任务关联**：6 道 medium / 8 张模板卡 / 计时记录

## Day 5 · 项目三系统设计与容量

**一句话**：面试官爱问“10 倍”，答案要有数字和顺序。

**核心知识**

- 容量估算：QPS、token、并发、存储、带宽、成本。
- 瓶颈顺序：上游配额/限流 → 连接池 → DB → 缓存 → CPU/GPU。
- 扩展：缓存、队列、批处理、分片、读写分离、降级。
- 容灾：供应商故障、超时、限流、区域故障。
- 成本：模型分级、缓存、上下文裁剪、批处理。

**速查**

```text
10x 流量：
1. 先算配额/成本
2. 加缓存/队列
3. 扩容连接池/DB
4. 降级非核心功能
5. 压测验证
```

**常见坑**

- 只说“加机器”，没有瓶颈分析。
- 忽略模型配额和成本，扩容也买不到 token。

**面试口述**

> 流量涨 10 倍，项目三哪里先崩？怎么扩展？

**深入理解**
- **机制**：容量估算按 QPS × token × 单价，考虑峰值、缓存、冗余和降级。
- **边界**：模型配额、连接池、DB、缓存和成本都可能先成为瓶颈；只加机器不一定买到 token。
**场景**：流量 10 倍：先算配额/成本，再加缓存/队列/降级，最后压测验证。
**追问**：Q：10 倍流量先崩哪？A：上游配额/限流、连接池、DB、缓存，按依赖排序。

**任务关联**：容量估算 / 3 个故障演练 / 扩展一页纸

## Day 6 · 全真模拟面试 1

**一句话**：模拟面试不是考知识，是练结构和抗压。

**核心知识**

- 45 分钟项目 + 45 分钟系统设计 + 15 分钟行为。
- 项目：背景→方案→取舍→指标→失败。
- 系统设计：需求→估算→架构→瓶颈→取舍。
- 行为：STAR，结果有数字。
- 录像复盘：卡顿、跑题、超时、被追问慌。

**速查**

```text
复盘表：问题 / 我的回答 / 卡点 / 更好结构 / 下次动作
```

**常见坑**

- 只练知识，不练表达和时间控制。
- 复盘只看“对不对”，不看结构。

**面试口述**

> 模拟面试最大的问题通常是什么？

**深入理解**
- **机制**：模拟面试检验结构、时间控制和抗压；录像回听比自我感觉可靠。
- **边界**：只练知识不练表达会超时/跑题；只看对错不看结构会重复犯错。
**场景**：45 分钟项目 + 45 分钟设计 + 15 分钟行为，全程录像复盘。
**追问**：Q：模拟面试最大问题是什么？A：结构乱、超时、只讲技术不讲取舍。

**任务关联**：全真模拟 / 录像 / 10 张追问卡 / 复盘

## Day 7 · 周复盘：弱项补洞

**一句话**：最后两周不开新坑，只补最影响面试的。

**核心知识**

- 按“影响 × 频率”排序弱项。
- 每个弱项：一份好材料 → 一页提纲 → 口述/做题 → 反馈 → 再讲。
- 系统设计/项目指标/行为故事是高频失分点。
- 保持算法手感，但不要刷难题找挫败。

**速查**

```text
本周最小验收：
[ ] 10 道设计提纲
[ ] 50 道八股速答
[ ] 8 类算法模板
[ ] 1 次全真模拟
[ ] 5 个弱项清单
```

**常见坑**

- 继续收集课程，不输出。
- 追求“全部学会”，导致面试延期。

**面试口述**

> 你目前最需要补的三个面试弱项？

**深入理解**
- **机制**：最后两周按“影响 × 频率”补弱项，不再开新坑。
- **边界**：从第一章系统学来不及；追求全部学会会拖延面试。
**场景**：每个弱项：一份好材料→一页提纲→口述/做题→反馈→再讲。
**追问**：Q：怎么选三个弱项？A：面试反馈里高频、影响通过率、可在两周内练会的。

**任务关联**：W14 周测 / 弱项清单 / W15 计划 / 周报
