# W11 · 项目二：Agent 工作流平台

> 阶段：Agent 工程（P3）｜Day 1–7
> 用法：先读当天小节，再去做学习舱任务；做完回来补“常见坑”。

## 本周主线

- 用 20 条任务集定义“什么算成功”，再设计工具和状态机。
- 做出可审批、可恢复、可追踪、可评测的 Agent 服务。
- 关键词是“可控”，不是“多智能体”。

## Day 1 · 需求、任务集与架构

**一句话**：先写任务集，再写 Agent；否则做完不知道好不好。

**核心知识**

- 任务集覆盖：简单、复杂多步、无解、越权、工具失败五类。
- 每条任务有明确成功标准：答案正确/动作完成/格式合法。
- 架构：API、编排引擎、工具运行时、状态存储、trace、评测。
- 权限矩阵：哪个工具、哪个角色、是否需要审批。
- 风险清单：越权、死循环、成本、记忆污染、工具失败。

**速查**

```text
任务集示例：
T01 查上周订单并汇总（简单）
T02 跨库对比 + 生成报告（复杂）
T03 问不存在的客户（无解）
T04 让 Agent 删除数据（越权）
T05 工具超时后重试（失败）
```

**常见坑**

- 任务集全是“顺风局”，线上第一次遇到边界就崩。
- 成功标准模糊，无法自动判定。

**面试口述**

> 为什么先写任务集再写 Agent？

**深入理解**
- **机制**：任务集定义成功标准和覆盖面，指导工具、状态和评测设计。
- **边界**：全是顺风局无法覆盖真实失败；成功标准模糊无法自动判定。
**场景**：20 条任务覆盖简单、多步、无解、越权、工具失败。
**追问**：Q：任务集怎么扩充？A：从真实用户请求、失败日志、边界场景和红队用例中补。

**任务关联**：PRD / 状态图 / 工具清单 / 20 条任务

## Day 2 · 工具集：搜索、SQL、知识库、文件

**一句话**：工具是权限和风险的集中地，先设计边界再写实现。

**核心知识**

- 统一工具协议：名称、描述、参数 schema、超时、错误、权限。
- SQL 工具：只读账号、表白名单、参数化、行级权限、查询超时、行数限制。
- 知识库工具：复用项目一 RAG，返回引用。
- 文件工具：沙箱目录、扩展名白名单、大小限制。
- 通知/写操作：幂等 key、审批、审计。

**速查**

```text
工具清单：search_web / query_sql / search_kb / read_file /
          calculate / send_notification
```

**常见坑**

- SQL 工具给管理员权限，一次注入全库泄露。
- 文件工具可以读任意路径，造成敏感文件泄露。

**面试口述**

> 给 Agent 的 SQL 工具，最关键的安全措施有哪些？

**深入理解**
- **机制**：工具集统一 schema、错误、超时和权限；SQL/文件等高风险工具要最小权限。
- **边界**：管理员权限会放大注入；没有超时会拖垮工作流；错误不结构化模型无法决策。
**场景**：SQL 只读、白名单、参数化、行级权限、查询超时和行数限制。
**追问**：Q：工具超时怎么处理？A：返回结构化超时错误，Agent 决定重试/换工具/降级。

**任务关联**：6 个工具 / 统一错误 / 正常+异常测试

## Day 3 · 状态机、审批与恢复

**一句话**：把高风险动作放进可暂停、可拒绝、可恢复的节点。

**核心知识**

- 图：理解 → 规划 → 工具 → 观察 → 生成 → 校验；高风险动作前审批。
- 审批状态：待审批动作、参数、风险、发起人、过期时间。
- 恢复前重新校验参数/权限/时效；拒绝走终止分支。
- 工具失败返回结构化错误，Agent 决定重试/换工具/终止。
- 重试要幂等、限次数、可观测。

**速查**

```text
execute_sql → 审批节点 → 通过 → 执行 → 记录审计
                      ↘ 拒绝 → 终止/给建议
```

**常见坑**

- 审批只做“通过”，没有拒绝和修改。
- 工具失败直接抛异常，整个工作流崩溃。

**面试口述**

> 工具失败时 Agent 应该怎么处理？怎么避免无限重试？

**深入理解**
- **机制**：状态机把规划、工具、审批、执行分开；checkpoint 支持恢复。
- **边界**：审批后不重新校验会执行过期/越权动作；工具重试不幂等会重复副作用。
**场景**：高风险动作前暂停，修改参数后恢复；失败从 checkpoint 重试。
**追问**：Q：怎么保证重试安全？A：幂等 key、去重表、事务和最大重试次数。

**任务关联**：状态机 / 审批 / 5 条恢复测试 / 审计

## Day 4 · 记忆、权限与审计

**一句话**：Agent 可以记住该记的，但必须能删、能纠错、能审计。

**核心知识**

- 会话记忆：最近消息 + 摘要；长期记忆：稳定偏好/事实。
- 记忆条目带 source/confidence/expires_at；区分用户陈述与模型推断。
- 权限：工具级 + 数据级；执行前校验，不依赖模型自觉。
- 审计：谁、何时、对什么资源、执行什么动作、结果。
- 隐私：敏感信息不写记忆；支持删除和导出。

**速查**

```text
memory = {content, source, confidence, tenant, created_at, expires_at}
audit = {actor, action, resource, args_hash, result, trace_id, at}
```

**常见坑**

- 把模型推断写入长期记忆，后续一直被错误前提带偏。
- 审计只记录最终答案，无法还原执行链。

**面试口述**

> Agent 的记忆如何避免污染？权限和审计怎么设计？

**深入理解**
- **机制**：记忆、权限、审计是 agent 落地的三条底线；模型不能自己决定权限。
- **边界**：模型推断写入记忆会污染；审计只记最终答案无法还原；敏感信息不能明文存。
**场景**：工具级 + 数据级权限，执行前校验；记录 actor/action/resource/result/trace。
**追问**：Q：记忆怎么删除？A：提供查看/删除/过期，删除时同步索引和缓存，并记录审计。

**任务关联**：记忆模块 / 权限矩阵 / 10 条越权测试 / 审计

## Day 5 · Trace、评测与成本

**一句话**：每次运行都要能回放，才能定位“为什么失败、花了多少”。

**核心知识**

- trace：每步 thought/action/observation、工具参数、耗时、token、错误。
- 指标：成功率、平均步数、工具错误率、人工干预率、单任务成本。
- 成功率按任务成功标准判定，自动 + 人工抽检。
- 多次运行取分布，避免单次幸运成功。
- 成本按模型 + 工具 + 检索分别统计。

**速查**

```text
20 条任务 × 3 次：
成功率 85% / 平均 5.4 步 / 工具错误率 6% / 干预率 10% / 成本 0.12 元/任务
```

**常见坑**

- 只统计模型 token，忽略检索/工具/重试成本。
- 成功率定义太宽，把“部分完成”算成功。

**面试口述**

> Agent 的成功率怎么定义？为什么还要看步数和成本？

**深入理解**
- **机制**：trace 记录每次 tool call；评测看成功率、步数、成本、工具错误率和干预率。
- **边界**：成功率定义太宽会虚高；只统计模型 token 会低估成本；单次运行不可靠。
**场景**：20 条任务 × 3 次，报告分布和失败分类，成本按模型+工具+检索拆。
**追问**：Q：成功率和效率怎么平衡？A：先达质量门槛，再优化步数和成本；不能为了步数牺牲正确性。

**任务关联**：trace / 20 条任务 / 指标报告 / 成本表

## Day 6 · 集成、demo 与文档

**一句话**：让面试官在 3 分钟内看到“可控”，而不是“多智能体”。

**核心知识**

- 最小 UI/CLI：发起任务、审批交互、运行历史、trace 查看。
- demo：正常任务 → 工具失败恢复 → 审批拒绝/改参。
- README：架构、工具协议、权限、评测、失败复盘。
- 项目二与项目一区分：重点是编排/审批/状态，不是重复 RAG。
- 视频 3 分钟：问题 → 流程 → 审批 → 指标。

**速查**

```text
Demo 顺序：
1. 一个多步任务
2. 工具失败后自动换工具
3. 高风险动作暂停审批
4. 展示 trace 和成功率
```

**常见坑**

- 演示只走成功路径，看不出“可控”。
- 项目二和项目一讲成同一个东西，浪费一个项目。

**面试口述**

> 用 10 分钟讲项目二，重点讲什么？

**深入理解**
- **机制**：项目二证明“可控”：状态、工具协议、审批、恢复、trace 和评测。
- **边界**：只演示成功路径看不出可控；重复项目一没有差异化。
**场景**：3 分钟演示多步任务、工具失败恢复、审批暂停/改参。
**追问**：Q：项目二和项目一的区别？A：项目一是检索与生成，项目二是编排、工具、审批和可观测。

**任务关联**：最小 UI / 3 个失败修复 / README / 视频

## Day 7 · 周复盘 + 项目二模拟面试

**一句话**：项目二的关键词是“可控”，不是“多智能体”。

**核心知识**

- 高频追问：为什么用 Agent？怎么防死循环/越权？怎么评测？
- 每个机制要有数据：成功率、步数、成本、干预率。
- 失败案例要具体：哪个工具、什么参数、怎么修。
- 与项目一的边界要清楚。

**速查**

```text
项目二 10 问：
为什么 Agent / 工具协议 / 审批 / 恢复 / 记忆 /
权限 / 死循环 / 评测 / 成本 / 失败复盘
```

**常见坑**

- 讲了一堆框架名，讲不清状态和权限。
- 没有真实任务集，指标不可信。

**面试口述**

> 项目二最容易被问倒的三个点是什么？

**深入理解**
- **机制**：项目二的高频追问围绕“为什么 agent、怎么防死循环/越权、怎么评测”。
- **边界**：没有任务集和指标，回答会空；没有失败案例，显得不真实。
**场景**：模拟 20 分钟深挖，记录 5 个被问住的点。
**追问**：Q：最容易被问倒什么？A：为什么不用 workflow、审批状态怎么恢复、成功率怎么定义。

**任务关联**：W11 周测 / 模拟面试 / 复盘 / 简历 bullet v2
